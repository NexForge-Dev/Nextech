# NEXTECH Own Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn NEXTECH into its own Brazilian electronics store (cart → in-site Stripe checkout with card/boleto, Pix behind a flag → orders managed manually in admin), while keeping the affiliate model intact and switchable.

**Architecture:** Own-store data lives in new tables (`product_sale`, `suppliers`, `product_suppliers`, `carts`, `orders`, `order_items`, `order_events`, `order_refunds`, `return_requests`, `stripe_events`). A `products.sale_mode` column plus two settings flags decide what the storefront shows; affiliate tables/code stay untouched and are only gated. Payments use Stripe PaymentIntents + Payment Element on NEXTECH pages; orders become paid only from the signature-verified webhook. Emails go through a tiny Resend HTTP client.

**Tech Stack:** Next.js 16.4 (App Router, server actions, `src/proxy.ts`), React 19.3, Tailwind 4 + shadcn, next-intl 4, Supabase (Postgres/RLS/Auth/Storage), zod 4, `stripe` (server), `@stripe/stripe-js` + `@stripe/react-stripe-js` (client), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-own-store-design.md`

## Global Constraints

- Own store: market `BR`, currency `BRL`, locale pt-BR only. Free shipping always ("Frete grátis").
- Money in integer minor units (centavos), as everywhere in the codebase (`src/lib/domain/money.ts`).
- Stripe fee constants (for estimates only; real fee comes from the balance transaction): card 3.99% + R$0.39 (`399` bps, `39` minor), boleto R$3.45 flat (`345` minor), Pix 1.19% (`119` bps). Boleto amount range R$5.00–R$49,999.99. Pix min R$0.50.
- Boleto cannot be refunded through Stripe → refunds of boleto orders are recorded as "reembolsado por fora" (manual) with amount/date/note.
- Order is paid only via webhook (`payment_intent.succeeded`). Never from the success page.
- Server recomputes every price/total from the DB; client amounts are ignored.
- Secrets only in env: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`, `RESEND_API_KEY`, `EMAIL_FROM`, `OWNER_ALERT_EMAIL`. Missing email env → emails are logged and skipped, never crash.
- Do not drop/alter-destructively any affiliate table, column, function, route, adapter or admin page.
- Customer-facing copy pt-BR; admin copy pt-BR (hardcoded, like the rest of admin); README/tech docs in English.
- Visual identity: black/white, reuse existing store/admin components.
- New store routes need entries in `src/i18n/routing.ts` `pathnames` (same pt path for all locales is fine: own store is pt-BR only).
- Customer statuses: `awaiting_payment`→"Aguardando pagamento"; `paid`, `awaiting_supplier`, `supplier_purchased`→"Em preparação" (with "Pagamento confirmado" as the first timeline step); `shipped`, `in_transit`→"Enviado"; `delivered`→"Entregue"; `cancelled`→"Cancelado"; `refunded`→"Reembolsado".
- CDC copy: "7 dias para desistir · garantia de 90 dias".

## Review Focus

1. Duplicate/out-of-order webhooks (same event twice, `succeeded` arriving after `payment_failed`, refund before succeeded) → order ends in the right state once, one confirmation email. Test in Task 7.
2. Price or availability changes between cart and payment (product edited, sold out, mode switched off) → checkout recomputes and blocks with a clear message; PaymentIntent amount always equals the order total. Test in Task 6.
3. Double-click "Pagar" / two tabs → one order and one PaymentIntent per checkout attempt (idempotency key = order id). Test in Task 6.
4. Customer cancelling while the owner registers a supplier purchase at the same time → cancellation refused once any item has `supplier_purchased_at`; guarded in SQL, not just UI. Test in Task 9.
5. A visitor reaching a hidden product (affiliate mode while affiliates OFF, or own mode while own store OFF) via old URL, `/go`, sitemap or search → never purchasable/redirected; `/go` returns 404-like redirect to the product page. Test in Task 3.
