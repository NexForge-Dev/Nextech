# NEXTECH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete NEXTECH affiliate storefront (public store in 4 locales + full admin panel + click tracking + affiliate network integrations), deploy-ready for Vercel + cloud Supabase.

**Architecture:** One Next.js App Router app. Public store under `src/app/[locale]/…` (next-intl, localized pathnames), admin under `src/app/admin/…` (PT-BR only), tracked redirect at `src/app/go/[productId]/route.ts`. Pure business rules live in `src/lib/domain/*` (unit-tested, no I/O). Data access lives in `src/lib/data/*` (server-only, Supabase). Every admin mutation is a Server Action guarded by `requirePermission()`, and the same rule is enforced again by Postgres RLS via `has_admin_permission()`.

**Tech Stack:** Next.js 16.x, React 19, TypeScript strict, Tailwind CSS 4.x, shadcn/ui, lucide-react, next-intl 4.x, @supabase/ssr 0.12.x + @supabase/supabase-js, zod, react-hook-form, Recharts, papaparse, sanitize-html + marked, Vitest, Playwright, Supabase CLI 2.x (local Docker).

**Spec:** `docs/superpowers/specs/2026-10-31-nextech-design.md` (decisions; wins on conflict) + `docs/superpowers/specs/2026-10-31-nextech-brief.md` (owner brief, PT-BR). Executors read both before starting any task.

## Global Constraints

- Palette is exactly `#000000 #FFFFFF #222222 #777777 #E5E5E5 #F7F7F7` (white overlays with opacity allowed). No other colour anywhere: no Tailwind colour scales (`blue-*`, `red-*`, `green-*`…), no colour status badges. Status = icon + text + weight.
- Fonts: Geist Sans, plus Geist Mono for SKUs/numbers in admin. Motion is 150–200 ms opacity/transform only. Light theme only.
- Locales `pt-BR` (default), `pt-PT`, `en`, `es`. URL prefixes are `/pt-br`, `/pt-pt`, `/en`, `/es`. Default market per locale is pt-BR→BR, pt-PT→PT, en→US, es→ES. A missing translation falls back to pt-BR.
- Admin UI is PT-BR only. `/admin` and `/go` are not localized.
- Never show a converted price. Never compute commissions from clicks. Every external fact has `source ∈ {manual, import, integration}`.
- Never show fabricated data as real. Sections without data are hidden. Admin empty data reads "Sem dados ainda", never zeros dressed as results.
- Local Supabase ports: shadow 55820, API 55821, DB 55822, Studio 55823, Inbucket 55824 (SMTP 55825, POP3 55826), analytics 55827, pooler 55829, inspector 55833. Dev server `next dev -p 3300`. Never stop other projects' Docker containers.
- The service-role key and network credentials appear only in modules importing `server-only`.
- Docs (README etc.) are in English. Store copy is in 4 languages, admin copy in PT-BR.
- Git: work on branch `feat/nextech-v1` (created from `dev`, which is created from the initial `main` commit). Commit after every task. Never push unless lint + typecheck + all tests + build pass. Merge to `main` only with owner approval.

## Review Focus

1. **A product with no offer in the visitor's market, or only `link_only` offers (Amazon)**: card and page render normally. No "R$ 0,00", no NaN, no discount. The card shows "Ver preço na loja", and the page lists the markets where the product is available. → tests in Task 4 (`bestOffer`) and Task 15 (e2e).
2. **A missing translation for the requested locale**: the pt-BR text is shown, never a blank title or a raw message key. → test in Task 12 (`pickTranslation`).
3. **An inactive or deleted product reached by an old URL or `/go` link**: a localized 404. `/go` returns 404 and never redirects to the store. → tests in Task 16.
4. **An admin pastes an `http://` URL, a short link (`amzn.to`), or a URL whose host is not in the store's domains**: a clear validation error naming the host and offering "adicionar domínio à loja". Amazon stores are seeded with `amzn.to` and the regional domains. → tests in Task 5 and Task 23.
5. **Search input that is accented, has SQL/LIKE metacharacters, or is very long** (`"café"`, `"%_\\'"`, 500 chars): no error, accent-insensitive results, input trimmed to 100 chars. → tests in Task 12.

### Task 4: Domain — pricing (best offer, proven discount, priceless offers)

**Files:**
- Create: `src/lib/domain/pricing.ts`
- Test: `tests/unit/pricing.test.ts`

**Interfaces:**
- Produces:
  ```ts
  type PriceDisplayPolicy = 'show' | 'link_only'
  type OfferForPricing = { id: string; market: MarketCode; currency: string; active: boolean;
    policy: PriceDisplayPolicy; priceMinor: number | null; priceUpdatedAt: string | null;
    previousPriceMinor: number | null; previousVerified: boolean;
    priceSource: 'manual' | 'import' | 'integration' | null; requiresFreshIntegration: boolean; // true for Amazon (PA-API) offers
    // displayPrice(o, now) also returns null when requiresFreshIntegration && (priceSource !== 'integration' || priceUpdatedAt older than 24 h)
    history: { priceMinor: number; observedAt: string }[] }  // from product_prices, newest first
  provenPrevious(o: OfferForPricing, now: Date): number | null
  discountPercent(currentMinor: number, previousMinor: number): number   // Math.round, integer
  displayPrice(o: OfferForPricing, now: Date): number | null   // null when link_only, no price, inactive, or stale integration price
  bestOffer(offers: OfferForPricing[], market: MarketCode, now: Date): OfferForPricing | null  // "priced" = displayPrice(o, now) !== null
  priceSummary(offers: OfferForPricing[], market: MarketCode, now: Date):
    { kind: 'price'; fromMinor: number; currency: string; multiple: boolean; previousMinor: number | null; discount: number | null }
    | { kind: 'link_only' } | { kind: 'unavailable'; availableMarkets: MarketCode[] }
  ```
- Rules: the previous price is proven if (a) `history` contains an observation within 90 days of `now` that is strictly higher than the current price (take the most recent such one; history rows older than the current price's `priceUpdatedAt` only), or (b) `previousVerified && previousPriceMinor > priceMinor`. Otherwise it is null. `bestOffer` = the cheapest active priced offer in the market, else the first active `link_only` offer in the market, else null. Ties go to the most recent `priceUpdatedAt`.

  - `previousVerified=false, previousPriceMinor=100000` and no history → `null`. With `previousVerified=true` → `100000`.
  - `bestOffer` picks the cheapest active priced offer in the market and ignores other markets' offers. With only a `link_only` offer it returns that offer.
  - `priceSummary` with two priced BR offers 5000/7000 → `{kind:'price', fromMinor:5000, multiple:true}`. With only Amazon `link_only` → `{kind:'link_only'}`. With offers only in PT and market BR → `{kind:'unavailable', availableMarkets:['PT']}`.
